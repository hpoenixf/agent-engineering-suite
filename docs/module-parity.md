# Module parity and intentional boundaries (0.1.0)

| Module | Existing capabilities retained | Adapted/new | Not claimed / deferred |
|---|---|---|---|
| Spec flow | Public CLI lint/verify/status, schema, synthetic tests, provenance and authored-status semantics | Standalone lifecycle skill wrapper | Structural checks do not execute or certify semantic acceptance |
| History | Public CLI init/candidate/snapshot/verify/validate, manual-region protection, timezone/event identity, original tests | Namespaced entry | No access to private agent conversations or automatic semantic summarizer |
| Grilling | Full design-tree, material-decision filter and staging instructions | Namespaced entry | No separate interview service |
| Architecture | Full ownership/deletion and deepening workflow, contract/lifecycle/hotspot audit and HTML report guidance | Portable entry | No autonomous code changes from review-only requests |
| Code review | Full standards/spec axes, fixed-base review and built-in smell baseline | Namespaced entry | No private source access implied |
| Docs maintenance | Evidence/source/generated-view separation | Local adapter and precise cleanup plan | Original ChatGPT-only GitHub integration is intentionally excluded; no permanent automatic deletion |
| Maturity | Generic 24-goal/28-capability/16-strategic profiles; Decimal calculators, scale fingerprints, comparison checks, review-lock item-change/attribution/drift guards and strict evidence fields | New scale identities and generic criteria; no private module mapping, owner codes or internal evidence paths; assessment must be explicitly supplied | Private baseline scores, source-discovery indexes, publication guards and historical migration are excluded, not silently replaced. No full private-plugin parity claim |
| Roadmap | Stable owner/evidence/state transition method | Portable standalone item template; independent from maturity | No project-specific validator until adapted/tested; no automatic status closure |
| Workflow | None: new suite entry | Optional routing and bounded acceptance/release/handoff templates | These templates are not an implemented acceptance runner or release orchestrator |

All module dependencies are optional workflow links, not mandatory runtime services. Unknown evidence stays unknown. The full suite is a version-consistent package of the same modules, not a stronger proof of capability.
